- Add the version 3 Construction workflow CLI for mission startup, Unit of Work creation, stage/task/Activity operations, Integration checks, audit history, and source-bound Git diff packages.
- Add `kepler mission prepare --mission <mission-id> [--project <path>]` for same-identity startup continuation, exact pending-event retries, conservative workspace reconciliation, and historical no-op reporting. Older incomplete missions without required local recovery facts fail explicitly.
- Add the Standard workflow: Functional Design, Quality Requirements, Implementation Planning, Implementation, Unit of Work Review, and Deliver. Implementation separates Code Generation, non-author Code Validation, and checked Code Integration.
- Ship eleven versioned portable skills, four Claude Code role definitions, versioned v3 Construction templates, compatible bundle setup, and an installation-generation receipt. Bundle `kepler-bundle-3.0.2` carries skills `kepler-skills-3.0.1` with inline reopening questionnaires and a self-contained Planning task-graph reference. Native bindings remain `claude-code-bindings-1.0.0`.
- Reject incomplete bundles before setup writes, including digest-consistent bundles missing any required v3 Construction template. Preserve existing resources, settings, and the installation receipt on that failure.
- Revalidate current Integration proof and lock ownership at acceptance. Serialize incomplete-work release with acceptance, reject superseded or failed proof, preserve replacement owners, and recover eligible accepted-event release without duplicate history. Keep separate `integration lock|prepare|evidence|accept|release` operations; the caller still runs the required checks.
- Report recorded prerequisite proof before task admission, with shared readiness/admission validation and consistent known/unknown results. Preserve valid facts for the same paused or completed parent, reject causally unbound proof, and permit fresh proof after an earlier Implementation attempt's admission. Queries remain read-only; admission still requires explicit evidence IDs.
- Add execa E2E coverage for greenfield and existing-application workflows, failure and recovery paths, multi-repository behavior, installer/standalone execution, and delivery effects. Add a packed-Core consumer that typechecks declarations and exercises public behavior.

## Compatibility and limits

The earlier `kepler workbench` command remains for change-based artifacts. Kepler does not convert earlier artifacts or history into v3 records. Keep active work with the generation that created it.

`kepler setup` installs compatible bundle resources and missing default settings; the host or skill manager installs portable skills and native agent definitions. Installation checks and executable tests do not certify agent behavior.

The release target set is Linux and macOS on x86_64 and arm64. CI configures native standalone checks for all four targets and keeps those results separate from Linux x64 cross-compilation. Consult completed CI runs for target-specific evidence. `RELEASE-MANIFEST.json` records the source commit, workflow run, and each distributable's SHA-256 digest; `SHA256SUMS` covers the distributables and manifest. GitHub artifact attestations bind each staged release asset to its build workflow. CI verifies the manifest, checksums, and attestations before creating the version tag and again before publishing. You can verify a downloaded asset with `gh attestation verify <asset> --repo vialactea-works/kepler`.

The Standard workflow does not automatically publish releases, deploy services, roll back changes, or delete user data. Those operations require separate authority.

Install the CLI and compatible sidecar bundle with the release installer, then install the matching skills and optional host definitions. See the [installation guide](../installation.md), [CLI guide](../cli.md), and [recovery guide](../recovery.md).
