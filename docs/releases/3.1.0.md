# Kepler 3.1.0

This release candidate makes coding-agent prompts the normal path through a Standard mission. It changes packaged resources and guidance, not the CLI interface or the Standard workflow contract.

## Added

- Adapt and package `kepler-init` as an optional project-readiness skill. It checks a Git worktree and local `.kepler/` marker without creating a mission or unit, scaffolding v2 artifacts, or handing off to another skill.
- Package `kepler-mission-startup` as the required pre-stage skill. It prepares a mission, creates or recovers its single Standard unit, and hands off before Functional Design.
- Package `kepler-resume` as an optional supporting skill for inspection and guarded interruption recovery. It returns work to the owning stage or Activity skill.
- Include package-local agent-operation recipes and a complete CLI walkthrough in the startup skill's references. The resource manifest now declares fourteen skills and eight Pi/Claude Code profiles.

## Changed

- The [developer tutorial](../missions/tutorial.md) now follows copyable prompts from startup through verified Deliver, with explicit requester decisions and an independent Review. Detailed commands remain in the [agent/operator walkthrough](../cli/standard-walkthrough.md) and [recovery operations](../cli/recovery-operations.md).
- Pi and Claude Code orchestrator profiles coordinate pre-stage startup and cross-stage recovery. Architects, coders, and non-author reviewers retain their existing stage and Activity ownership. Existing skills now point agents to the packaged request and handoff recipes.

## Compatibility

The five source-only legacy skills (`kepler-compose-spec`, `kepler-critique`, `kepler-propose`, `kepler-wayfinder`, and `kepler-wayfinder-prototype`) are removed. Existing workbench commands, historical data, and their templates remain available; no migration is implied.

The CLI commands and request/response contracts, six Standard stages, task Activities, checks, approval rules, release-bound setup, and delivery authority remain unchanged. The 3.x artifact schema remains version 3. The earlier `workbench` surface and legacy data are not converted. Each installed version needs its matching resource home, and a host must separately load its skills and profiles. Setup does not install a CLI or register agent resources.

## Verification and limits

Package and CLI tests check resource completeness and workflow mechanics, not whether a particular coding-agent host follows the prompts. Native archive/host certification, genuine requester approvals in a live agent exercise, publication, and deployment require separate evidence and authorization. An open PR is not a published release.
