# Kepler 3.0.0 — unreleased candidate

**Status:** This is a release-candidate note for the uncommitted implementation. Kepler 3.0.0 has not been published. No installation or publication is authorized by this note.

## Added

- One authored Kepler version and a complete resource manifest for the CLI, templates, guidelines, eleven skills, and four Pi-native role profiles.
- Setup registration of Kepler's Pi package and a single generation selector. Pi and pi-subagents retain discovery, loading, and execution ownership.
- A format-two installation receipt with a read-only format-one transition path.
- An isolated `dev:package` flow that tests a complete development archive without replacing a user's stable installation.

## Changed

- The installer now selects one target-specific versioned archive, verifies it, and invokes that candidate's setup. Setup alone activates the generation and stable command path.
- Setup validates source, target, resource, and archive identities; it preserves existing project data, settings, unknown resources, and prior generations.
- Pi setup requires Pi 1.2.0, pi-subagents 0.76.1, an existing agent directory, and initialized settings. A native ownership transfer requires review of the exact plan and `kepler setup --accept-native-transfer <digest>`.
- The old split sidecar flow is replaced for the candidate by resources packaged with the executable. Claude Code role definitions remain separate and are not installed or translated by Pi setup.

## Fixed

- Candidate activation is owned by setup rather than a second installer promotion.
- Setup rejects missing or unsupported Pi prerequisites, incomplete or mismatched archives, visible resource conflicts, and unsafe transfer plans before unqualified activation.
- Transfer consent is bound to the exact plan. It does not authorize unknown, custom, modified, or mixed resources.
- Bootstrap cleanup checks the identity of its owned staging directory; failed candidate evidence is retained for inspection.

## Compatibility

- The 3.x line keeps artifact `schema_version` 3. Receipt, resource-manifest, event, and CLI envelope formats have separate counters.
- Existing schema-3 artifacts, journals, legacy workbench data, and custom settings are not converted or deleted by setup.
- The initial Pi host contract is limited to Pi 1.2.0 and pi-subagents 0.76.1. Resource discovery does not certify agent behavior, credentials, permissions, or session reload.
- Linux and macOS on x86_64 and arm64 remain intended targets. Only a target's actual native run establishes execution evidence.
